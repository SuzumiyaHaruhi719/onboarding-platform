# 新员工入职阅读平台 · 设计文档

- **日期**:2026-06-08
- **状态**:已批准(头脑风暴定稿)
- **类型**:Web 应用(类 Kognity 的强制阅读式入职学习平台)

---

## 1. 产品概述

面向新员工的入职阅读/学习网站。两个角色入口——**学员**与**编辑者**。学员必须**完整阅读文档、看完视频、答对题目**才能逐节解锁、推进;**不得以任何形式跳过**。编辑者可上传文档(pptx/pdf/docx/txt/md 等),由多模态 agent(**qwen3.7-plus**)转译为符合设计规范的内容块,也可上传视频、插入题目。网站支持浅色/深色双主题切换与中英双语,实时记录完成进度。

设计规范来源:`GLP-light.md`(浅色)、`GLP-dark.md`(深色),核心品牌色浅色 `#00AA4F` / 深色 `#2FD47A`。

---

## 2. 范围与分期

项目较大,按可独立交付分期。每期各自走 spec → plan → 实现。本设计文档聚焦 **P1** 设计透,后续期次概述其目标。

| 期次 | 目标 | 交付物 |
|---|---|---|
| **P1 基座 + 学员核心** | 设计 token(双主题 + 切换 + 中英双语骨架)、角色选择、数据模型、内容块渲染器、三栏阅读界面、**服务端权威的防跳过**、进度记录、三题型 + 板块门禁。种子数据填充内容。 | 学员可完整走完一套被强制的入职课程 |
| **P2 编辑器** | 块编辑器(手动增删改块)、视频上传、出题、发布流程 | 编辑者无需 AI 即可手工创作课程 |
| **P3 多模态转译** | 文件上传 → qwen3.7-plus → 内容块,异步任务 + 进度,编辑者复核/微调 | 上传文档自动转成课程 |
| **P4 硬化** | 真鉴权(可插拔)、编辑者分析看板、响应式/无障碍打磨、fallow + codex 审计收尾 | 生产可用 |

> 本次实现从 **P1** 开始。

---

## 3. 技术栈

- **框架**:SvelteKit 全栈单体(页面 + `+server.ts` API 路由),TypeScript 严格模式
- **数据库**:SQLite + Drizzle ORM(轻量、零运维;fallow 原生支持 Drizzle)
- **样式**:纯 CSS 自定义属性(直接搬两份设计规范的 token),**不引重型 UI 库**
- **多模态 agent**:qwen3.7-plus,经 DashScope OpenAI 兼容端点 `/chat/completions` 调用(P3)
- **密钥**:全部走环境变量(`process.env`),绝不入库、不入代码、不入提交

### 选型理由
SvelteKit 一体化单仓库 → **可维护性最好**、运行时最轻、性能最佳;fallow 原生支持 SvelteKit;纯 CSS 变量最贴设计规范且零额外体积。

---

## 4. 架构与模块划分

SvelteKit 单体,`src/lib` 按领域拆成小模块(高内聚低耦合,文件 200–400 行,边界用清晰接口,便于 fallow 检测与 codex 审计):

- `lib/design/` — 设计 token(浅/深)、主题切换、全局样式
- `lib/content/` — 内容块类型定义 + 各块渲染组件
- `lib/anti-skip/` — 防跳过规则引擎(服务端权威)+ 客户端心跳采集
- `lib/db/` — Drizzle schema + 查询封装
- `lib/i18n/` — 中英双语机制
- `lib/agent/` — qwen 客户端(P3)
- `routes/` — 角色选择、学员阅读、编辑器(P2+)、API 路由

## 5. 数据模型(SQLite + Drizzle)

| 表 | 关键字段 |
|---|---|
| `User` | id, name, **role**(`learner` / `editor`) |
| `Module` | id, title, order |
| `Section` | id, moduleId, title, **order**(阅读+门禁最小单位) |
| `Block` | id, sectionId, **type**, order, content(JSON) |
| `Quiz` | id, sectionId, **type**(single/multiple/boolean), question, options(JSON), answer(JSON) |
| `Progress` | userId, sectionId, status, readPct, dwellMs, videoWatchedPct, quizPassed, completedAt |
| `IngestionJob` | id, file, status, progress, resultBlocks(JSON)（P3） |

---

## 6. 内容模型(结构化块)

块类型:`heading` / `paragraph` / `image` / `list` / `quote` / `callout` / `video` / `quiz`。
每块按设计规范渲染(扁平、有机圆角、品牌色点缀)。**Section** 是阅读与门禁的最小单位,内部块按 `order` 顺序排布。

---

## 7. 防跳过系统(服务端权威 —— 核心)

> 原则:**前端只是壳,完成判定全部在后端校验**,改前端无法绕过。

### 客户端采集(心跳上报)
- 滚动位置 / 是否到底
- 累计停留时长(失焦时暂停计时)
- 视频 `timeupdate` 的已观看区间

### 服务端校验规则(解锁需「四项防作弊措施」+「题目答对」全部通过)

**四项防作弊措施(均启用):**
1. **视频禁止快进**:进度条不可前拖;已观看区间必须连续覆盖全片才算看完
2. **切屏自动暂停**:标签页失焦/最小化时,客户端暂停视频与计时;服务端忽略失焦期间时长
3. **最短停留时长**:每节按内容长度估算最短阅读时间,未达不解锁
4. **滚动到底 + 关键段停留**:正文须滚动到底且关键段落有停留

**外加门禁条件:**
5. **题目答对**:本节题目(单选/多选/判断)全部答对

### 解锁机制
四项全过 → 服务端签发"本节完成" → **解锁并下发下一节内容**。未完成时下一节内容**根本不下发**到客户端。

## 8. 学员体验(三栏 · Kognity 风格)

- **左**:章节目录树,带锁定 / 进行中 / 已完成状态
- **中**:正文 + 视频
- **右**:进度环 + 置灰"继续"按钮(悬停提示还差什么)
- 视觉走**克制风格**(B 方案):深色为主、绿色仅作功能点缀,符合 GLP-dark "中性深灰 + 品牌绿点缀" 哲学

---

## 9. 主题与语言

- 两份设计规范 token 全搬进 CSS 变量
- `html[data-theme]` 切浅/深;`html[lang]` 切中英;均存 localStorage
- 严格遵守规范禁忌:无胶囊按钮、自定义下拉(非原生 select)、深色无彩色辉光、不在 `surface-page` 上裸排文字等

---

## 10. 题目系统

- 题型:**单选 / 多选 / 判断**,全部自动判分
- 答错 → 不解锁下一板块;支持重答
- 编辑者出题在 P2

---

## 11. 鉴权(渐进式)

- **P1**:不做真登录,入口仅"**角色选择**"(进站选 学员 / 编辑者)
- **P4**:真鉴权按需插入(账号密码 + 角色,密码哈希;接口与角色模型 P1 已预留)

---

## 12. 工程约束

- **可维护性优先**:小文件、清晰模块边界、TypeScript 严格模式
- **死代码治理**:每隔几轮跑 `npx fallow audit` 与 `npx fallow dead-code`,清理死代码
- **协同审计**:用 codex 协同做 audit 和 debug
- **轻量高性能**:不引重型 UI 库;纯 CSS 变量;SvelteKit 按需加载;SQLite 零运维
- **安全**:密钥仅环境变量;所有完成判定服务端校验;输入在边界校验
